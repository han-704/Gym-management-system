**用例编号**  1
**测试目的**  验证图片上传的格式校验机制——支持格式与非法格式的拦截
**前置条件**  系统可正常登录，用户具有文件操作权限（管理员/员工/会员）
**测试方法**  黑盒测试 + 接口验证
**测试步骤**  分组执行以下格式校验场景：

**A组——通用file-upload组件格式测试（会员卡类型/员工头像等模块）：**
1. 以管理员身份登录，进入"会员卡类型管理"→"新增"，定位到"会员卡图片"上传区域；
2. 分别上传以下格式的文件：
   - A1: 标准JPG图片（test.jpg, 200KB）
   - A2: 标准PNG图片（test.png, 150KB）
   - A3: GIF动图（test.gif, 500KB）
   - A4: WebP格式图片（test.webp, 100KB）
   - A5: BMP位图（test.bmp, 300KB）
   - A6: SVG矢量图（test.svg, 10KB）
   - A7: PDF文档（test.pdf, 200KB）
   - A8: 文本文件（test.txt, 5KB）
   - A9: 可执行文件（test.exe, 50KB）

**B组——心得分享封面图片格式测试（accept="image/*"限制）：**
1. 进入心得分享→发布心得，定位到"封面图片"上传区域；
2. 上传同A组的9种格式文件，观察accept="image/*"的过滤效果。

**C组——教练资质文件格式测试（accept=".pdf,.jpg,.jpeg,.png"+beforeCertUpload校验）：**
1. 进入个人中心→教练信息编辑，定位到"教练资质"上传区域；
2. 分别上传：C1=PDF文件、C2=JPG、C3=PNG、C4=GIF、C5=DOCX文档
**测试数据**  各类格式测试文件各1个，覆盖合法与非法格式
**预期结果**  
**A组（通用file-upload组件）：**
- A1-A4（JPG/PNG/GIF/WebP）：前端选择框正常弹出，文件选中后上传至后端POST /file/upload接口，返回code=0及文件名（时间戳+扩展名），预览区显示缩略图
- A5-A9（BMP/SVG/PDF/TXT/EXE）：行为取决于file-upload组件是否内置accept限制；若无accept限制则会上传成功（因FileController未做扩展名校验），若有则被前端过滤

**B组（心得分享accept="image/*"）：**
- B1-B4（JPG/PNG/GIF/WebP）：系统文件选择器仅显示图片类型文件，选中后通过http-request自定义上传成功
- B5-B9（BMP/SVG/PDF/TXT/EXE）：操作系统文件对话框中这些类型可能不可选或灰色；若强制传入非图片文件，浏览器el-upload组件会根据accept="image*"在文件选择阶段即拦截

**C组（教练资质beforeCertUpload严格校验）：**
- C1-C3（PDF/JPG/PNG）：通过beforeCertUpload扩展名检查（allowedExtensions包含.pdf/.jpg/.jpeg/.png）和大小检查（≤5MB），上传成功并提示"资质文件上传成功"
- C4（GIF）：扩展名.gif不在allowedExtensions列表中，提示"仅支持 PDF、JPG、PNG 格式的文件"，上传被阻止
- C5（DOCX）：同理被拦截，提示同上
**实际结果**  合法图片格式（JPG/PNG/GIF/WebP/BMP）均可通过通用组件上传；心得分享封面因accept="image/*"限制仅接受图片类型；教练资质因beforeCertUpload严格白名单仅允许PDF/JPG/PNG四种格式，其他均被拦截

**用例编号**  2
**测试目的**  验证文件大小限制机制——防止超大文件上传的安全防护
**前置条件**  同用例1
**测试方法**  边界值分析
**测试步骤**  分层测试三层大小限制：

**第一层——Spring Boot全局配置限制（application.yml）：**
1. 准备以下大小的JPG文件：
   - F1: 9.5MB（接近但小于10MB上限）
   - F2: 10.0MB（恰好等于10MB上限）
   - F3: 10.5MB（超过10MB上限）
   - F4: 15MB（显著超限）
   - F5: 50MB（极端超大）
2. 通过任意上传入口（如会员卡图片上传）分别尝试上传上述文件；
3. 观察后端日志是否出现MaxUploadSizeExceededException。

**第二层——前端教练资质beforeCertUpload业务限制（center.vue）：**
1. 在教练资质上传区域分别上传：
   - G1: 4.8MB的PDF文件（<5MB）
   - G2: 5.0MB的PDF文件（=5MB边界值）
   - G3: 5.5MB的PDF文件（>5MB）
   - G4: 8MB的JPG文件（超过5MB但在10MB以内）
2. 观察前端拦截提示。

**第三层——并发大文件压力测试：**
1. 同时选择3个接近上限的大文件（每个约9MB）进行批量上传（file-upload组件limit=3, multiple=true）；
2. 观察总请求大小（约27MB）是否触发max-request-size=10MB的全局限制。
**测试数据**  
F1-F5: 不同大小的JPG测试文件
G1-G4: 不同大小的PDF/JPG文件
**预期结果**  
**第一层（Spring Boot max-file-size=10MB, max-request-size=10MB）：**
- F1（9.5MB）：上传成功，文件完整写入classpath:static/upload/目录
- F2（10.0MB）：取决于Spring Boot对边界的处理（通常≤10MB可通过）
- F3（10.5MB）：后端抛出MaxUploadSizeExceededException，返回HTTP 500或由全局异常处理器捕获返回友好错误提示，文件未被写入磁盘
- F4/F5（15MB/50MB）：同F3，请求直接被Servlet容器拒绝，不到达Controller层
- 前端收到错误响应后在catch块中显示错误提示，不会导致页面崩溃

**第二层（教练资质5MB业务限制）：**
- G1（4.8MB）：通过beforeCertUpload的file.size ≤ 5*1024*1024判断，上传成功
- G2（5.0MB）：等于边界值，通过校验（通常size > maxSize才拦截）
- G3（5.5MB）：前端拦截，提示"文件大小不能超过 5MB"
- G4（8MB）：虽然未超过Spring Boot全局10MB上限，但被beforeCertUpload业务规则拦截

**第三层（并发多文件总大小超限）：**
- 3个×9MB = 27MB远超max-request-size=10MB
- Servlet容器在解析multipart请求体时即拒绝整个请求
- 返回413 Payload Too Large 或类似状态码
- 所有3个文件均未上传成功
**实际结果**  Spring Boot 10MB全局限制有效拦截F3(10.5MB)/F4(15MB)/F5(50MB)；教练资质5MB业务限制正确拦截G3(5.5MB)/G4(8MB)；并发27MB总请求量触发max-request-size限制被容器拒绝

**用例编号**  3
**测试目的**  验证上传成功后的文件存储路径正确性与文件可访问性
**前置条件**  系统正常运行，后端upload目录可写
**测试方法**  路径追踪 + 访问验证
**测试步骤**  1. 以管理员身份登录；2. 进入"会员卡类型管理"→新增一张会员卡；3. 上传一张测试图片（test_photo.jpg, 256KB）；4. 提交表单保存记录；5. 执行以下验证操作：
    **路径验证：**
    a) 检查后端返回的文件URL格式（应为 {baseUrl}/upload/{timestamp}.jpg ）
    b) 检查服务器磁盘上实际存储路径：{projectRoot}/back/src/main/resources/static/upload/{timestamp}.jpg 是否存在
    c) 检查数据库huiyuankaleixing表中该记录的huiyuankatupian字段存储的是完整URL还是纯文件名
    d) 检查前端回显时是否有../../../upload路径替换逻辑（reg=new RegExp('../../../upload','g')）

    **访问验证：**
    e) 直接在浏览器地址栏输入 http://localhost:8080/springboot97s0t/upload/{timestamp}.jpg ，确认能否访问图片
    f) 在会员卡类型列表页查看刚添加的记录，图片缩略图是否正常显示
    g) 进入该记录详情页，图片是否以大尺寸正常展示
    h) 点击图片触发el-image preview功能（preview-src-list），查看大图弹窗是否正常渲染

    **跨模块复用性验证：**
    i) 用同一张图片分别在以下模块各上传一次：
       - 会员卡类型（huiyuankaleixing → huiyuankatupian字段）
       - 员工/教练头像（yuangong → touxiang字段）
       - 心得分享封面（xindefu → fengmian字段）
       - 教练资质文件（yuangong → jiaolianzizhi字段，center.vue页面）
       - 会员头像（center.vue → huiyuan touxiang字段）
    j) 确认所有模块的上传均走同一 /file/upload 接口，存储在同一 upload/ 目录下
**测试数据**  test_photo.jpg (256KB, 800×600像素)
**预期结果**  
**路径验证：**
- a) 后端FileController.upload()返回R.ok().put("file", "1736000000000.jpg")，仅含纯文件名（不含路径前缀）
- b) 磁盘实际路径：{项目根目录}/back/src/main/resources/static/upload/1736000000000.jpg，文件存在且大小与原始文件一致

  - file-upload组件（会员卡/头像）：存完整URL（含baseUrl前缀）
  - 自定义upload方法（心得分享/资质）：form.fengmian = this.$base.url + "upload/" + data.file
- d) 前端add-or-update.vue中有reg=new RegExp('../../../upload','g')替换逻辑，将相对路径转为绝对路径用于回显

**实际结果**  文件统一存储至static/upload/目录，命名规则为{时间戳}.{扩展名}；五个模块（会员卡/员工头像/心得封面/教练资质/会员头像）均共用/file/upload接口；数据库存储完整URL；InterceptorConfig正确排除/upload/**路径实现免鉴权访问；列表/详情/预览三级视图均能正常加载图片

**用例编号**  4
**测试目的**  验证文件下载功能与异常安全性
**前置条件**  至少有一条包含上传文件的记录存在于数据库中
**测试方法**  功能测试 + 异常注入
**测试步骤**  

**A组——正常下载测试：**
1. 调用GET /file/download?fileName={已存在的文件名}接口；
2. 验证响应头Content-Type为application/octet-stream；
3. 验证Content-Disposition包含attachment指令和正确的filename参数；
4. 验证HTTP状态码为201 CREATED；
5. 验证响应体字节数与源文件完全一致。

**B组——异常输入测试：**
1. 调用GET /file/download?fileName=（空文件名）；
2. 调用GET /file/download?fileName=not_exist_file.jpg（不存在的文件）；
3. 调用GET /file/download?fileName=../etc/passwd（路径遍历攻击）；
4. 调用GET /file/download?fileName=....//....//etc/passwd（双重编码遍历）；
5. 调用GET /file/download（无fileName参数）。

**C组——文件预览完整性测试：**
1. 在员工信息详情页（type='info'模式）查看头像预览区：
   - el-image组件是否正确绑定ruleForm.touxiang.split(',')拆分的多张图片
   - :preview-src-list属性是否正确传递图片URL数组
   - 点击图片是否能打开全屏预览弹窗
   - 多张图片时左右切换箭头是否可用
2. 在心得分享详情页查看封面图片预览：
   - img标签的:src是否正确绑定form.fengmian
   - 上传新图片后img是否实时替换为新的base URL
3. 在会员卡类型详情页查看卡片图片预览：
   - image-preview区域的v-for循环是否遍历ruleForm.huiyuankatupian.split(',')
   - 图片fit="cover"裁剪模式是否生效
**测试数据**  已存在的上传文件名（如1736000000000.jpg）；各类异常字符串
**预期结果**  
**A组（正常下载）：**
- 响应码201，Content-Type=application/octet-stream
- Content-Disposition: attachment; filename="{原文件名}"
- 下载的文件内容与服务器磁盘上的源文件MD5/SHA1一致
- 浏览器自动触发文件下载保存对话框

**B组（异常安全）：**
- 空文件名：File构造得到无效路径，file.exists()返回false，返回HttpStatus.INTERNAL_SERVER_ERROR(500)
- 不存在的文件：同上，file.exists()返回false，返回500
- 路径遍历(../etc/passwd)：由于fileName直接拼接到upload目录下（new File(upload.getAbsolutePath()+"/"+fileName)），理论上可访问到upload父目录之外的文件——这是当前实现的潜在安全风险点
- 无fileName参数：@RequestParam注解要求必传，Spring MVC返回400 Bad Request
- 注：当前FileController.download()缺少路径规范化 sanitize 处理，建议后续增加fileName安全校验

**C组（预览功能）：**
- 员工头像预览：avatar-preview区域的el-image正确渲染多张图片（split按逗号分割），preview-src-list传递完整URL数组，点击触发Element UI原生图片查看器
- 心得分享封面：img标签src实时更新为新上传图片URL（this.$base.url + "upload/" + data.file），上传后立即显示新图
- 会员卡图片：image-preview区域v-for遍历多张图片，fit="cover"保持比例填充容器，点击可预览大图
- 图片加载失败时：el-image组件自带error事件（handleAvatarError），设置avatarLoadError标志位可显示占位图
**实际结果**  正常文件下载功能工作正常（201状态码+octet-stream类型+attachment触发浏览器下载）；不存在文件返回500；路径遍历攻击存在安全隐患（fileName未经sanitize直接拼接）；三个模块的图片预览功能（el-image/el-image/img标签）均能正常展示上传后的图片，支持单图/多图/大图预览

### 关键技术实现对照

| 功能模块 | 实现位置 | 核心逻辑 |
|---------|---------|---------|
| 统一上传接口 | FileController.upload() | POST /file/upload → MultipartFile接收 → static/upload/{时间戳}.{ext} → transferTo(dest) |
| 全局大小限制 | application.yml | `spring.servlet.multipart.max-file-size: 10MB`, `max-request-size: 10MB` |
| 业务格式/大小校验 | center.vue beforeCertUpload() | 白名单[.pdf,.jpg,.jpeg,.png] + size ≤ 5MB |
| 通用上传组件 | file-upload（全局注册） | `<file-upload action="file/upload" :limit="3" @change="xxx">` |
| 心得封面上传 | xindefu/add-or-update.vue uploadPicture() | el-upload + accept="image/*" + http-request自定义 → form.fengmian = $base.url+"upload/"+data.file |
| 教练资质上传 | center.vue uploadCertFile() | el-upload + accept=".pdf,.jpg,.jpeg,.png" + beforeCertUpload + limit=3 → jiaolianzizhi字段逗号拼接 |
| 文件下载 | FileController.download() | GET /file/download?fileName=xxx → ResponseEntity<byte[]>(octet-stream, attachment, 201) |
| 静态资源放行 | InterceptorConfig.java | excludePathPatterns("/upload/**") 免鉴权，支持图片直链访问 |
| 路径替换 | add-or-update.vue | reg=new RegExp('../../../upload','g') 将相对路径转绝对路径用于回显 |

### 发现的安全风险

| 风险项 | 位置 | 描述 | 建议 |
|--------|------|------|------|
| 路径遍历漏洞 | FileController.download():94行 | fileName参数未经sanitize直接拼接至文件路径，攻击者可通过`../`访问upload目录外的敏感文件 | 增加FileNameUtils.normalize() + 白名单扩展名校验 + 路径合法性检查 |
| 无扩展名白名单 | FileController.upload():53行 | 仅提取扩展名做文件名后缀，未校验是否为合法图片/文档扩展名 | 增加 allowedExtensions 白名单（jpg/png/gif/pdf/webp 等） |
